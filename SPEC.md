Cutline: SPEC
Read only the section for the phase you are on, plus "Global rules".
Product
Cutline is a desktop video editor for cutting long footage into finished clips: import, cut, arrange on a multi-track timeline, add titles and captions, colour and audio work, export. It runs fully offline with no account and no network calls. Owner and sole rights holder: Chamod Gimhan.
Target quality: the core editing workflow of a professional editor (timeline, trim tools, keyframes, audio, captions, export), frame-accurate and tested. The design is original. Do not copy another product's name, icons, or layout.
Out of scope for v1
Multicam, motion tracking, plugin hosts (VST, OFX), nested sequences, HDR and 10-bit pipelines, camera RAW, cloud or collaboration, bundled AI models. List these in the README as not supported. Never show a control for them.
Global rules

* Time. All times in the model are integer ticks, 705,600,000 per second (divides 23.976, 24, 25, 29.97, 30, 50, 59.94, 60 fps and 44.1/48 kHz exactly). No float seconds in the model or commands. Frame rates are rationals (30000/1001, not 29.97).
* One renderer. `renderFrame(project, tick)` and `renderAudio(project, range)` are the only paths to pixels and samples. Preview and export both call them.
* Commands. Every change to a project is a command object with `apply` and `invert`. No UI code mutates the model directly.
* Invariants (checked in tests after every command): clips on one track never overlap; no negative times; clip source range stays inside its media; ids are unique; a locked track never changes.
* Engine. WebCodecs for decode and encode, Web Audio (OfflineAudioContext) for mixing, WebGL2 compositor with a Canvas 2D fallback, heavy work in workers. Check codec support at runtime with `isConfigSupported`; never offer a format the machine cannot produce.
* Tooling. In phase 0, list what is already installed (node, tsc, bundler, test runner, headless Chrome, ffmpeg). If package installs are blocked, build with what exists and write the missing piece (for example an MP4 muxer) as a tested module. Log each case.
* Dependencies. MIT, BSD, Apache-2.0, ISC or MPL-2.0 only. No GPL or AGPL code. No FFmpeg inside the shipped app; ffmpeg may be used only to create and check test fixtures.
* Performance budgets (measured in tests, numbers logged): timeline with 2,000 clips stays interactive (frame under 32 ms while scrolling); scrub shows a frame within 150 ms on 1080p fixtures; memory stays flat over a 30-minute playback soak; a 2-hour source opens without being read fully into memory.
* Errors. Every failure the user can cause (corrupt file, missing media, unsupported codec, disk full, cancelled export) shows a plain message and leaves the project intact. Each has a test.

Phase 0: Scaffold
Repo, strict TypeScript, lint, unit test runner, `npm run verify`, theme file, PROGRESS.md, ARCHITECTURE.md, git. Fixture generators: 2 s 320x180 clips at 24, 25, 30000/1001 and 60 fps with a burned-in frame counter and a 1 kHz tone with a click each second; one 2-hour synthetic file; one variable-frame-rate file; one file with rotation metadata; one corrupt file. Done when: verify passes; fixtures regenerate byte-identical; PROGRESS.md lists installed tools and any blocked installs.
Phase 1: Core model and commands (pure TypeScript)
Model: project, media pool, sequences (size, rational fps, sample rate), tracks (video, audio, caption; order, lock, mute, solo, hide), clips (media id, source in/out, start, speed, properties, effects), markers, caption cues. Time math and frame snapping. Commands: add, remove, move, split, trim in/out, ripple trim, ripple delete, roll, slip, slide, insert, overwrite, lift, extract, link/unlink audio, track add/remove/ reorder, marker ops. Undo/redo history with grouping. Snapping calculation as a pure function. Project JSON (`.cutline`) with a schema version and migrations. Done when: every command has unit tests including edge cases (zero length, track edges, locked tracks, linked clips); a property test runs 10,000 random command sequences with invariants holding after each step and full undo returning a deep-equal project; save then load is deep-equal; a v1 fixture file migrates.
Phase 2: Media import and decode
Import by picker and drag-and-drop. Probe: duration, rational fps, VFR detection, rotation, pixel size, audio channels and rate. Demux and frame-accurate decode with a bounded frame cache. VFR sources are mapped to sequence frames by presentation time. Audio decode in chunks. Thumbnails and waveform peaks built in a worker and cached. Media is referenced by path plus fingerprint; missing media shows as offline and can be relinked. Done when: frame N of every fixture decodes to its stored hash and shows the right burned-in counter, including the VFR and rotated files; random seeks return the same frames as sequential decode; the 2-hour file opens within budget; the corrupt file gives a readable error; relink works in a test.
Phase 3: Compositor and playback
`renderFrame`: track stacking, transform (position, scale, rotation, anchor), crop, opacity, blend modes, sequence-size fitting. Playback clock driven by audio. Play, pause, J/K/L shuttle, frame step, loop between in and out, preview quality (full, half, quarter). Program and source monitors. Dropped preview frames never shift audio. Done when: the render check passes (fixed frames of the fixture project match stored hashes); audio/video drift stays under one frame over a 10-minute synthetic sequence; measured playback fps is logged; scrub meets its budget.
Phase 4: Timeline and editing UI
Panels: media bin, source monitor, program monitor, timeline, inspector, audio meters, history; resizable, layout saved. Timeline: virtualized tracks and clips with thumbnails and waveforms, zoom, scroll, playhead, in/out range, multi-select and marquee. Tools: select, razor, ripple, roll, slip, slide, hand, zoom. Snapping with a visible indicator. Drag from bin; three-point insert and overwrite from the source monitor. Markers. Copy, paste, duplicate. Context menus. Shortcut map with an editor and conflict detection. Done when: a browser smoke test drives each tool with real pointer and key events and the resulting model equals the expected model; every menu item, button and shortcut resolves to a command and each is run in a test; the 2,000-clip budget is met; typing in a field never fires a shortcut.
Phase 5: Audio
Clip gain, fade in/out, track volume and pan, mute and solo, keyframed volume, peak meters, audio scrub. Sample-accurate cuts with a short automatic crossfade at edits to prevent clicks. Mixdown through `renderAudio`. Loudness measurement (integrated LUFS) and normalise to a target. Detach and relink audio. Done when: mixdown of the fixture project matches stored samples within 1 LSB; the click-per-second fixture stays aligned to its frame counter after 50 edits; no sample jump above threshold at any cut; meter peaks equal computed peaks; LUFS matches a reference value within 0.2 LU.
Phase 6: Keyframes, effects, transitions, speed
Keyframe engine: linear, hold, bezier with editable handles; keyframe lane in the timeline. Effects with ordered stacks: exposure, contrast, saturation, temperature and tint, curves, LUT (.cube), blur, sharpen, vignette, chroma key, flip. Adjustment clips. Transitions: cross dissolve, dip to black, dip to white, wipe, slide, audio crossfade. Speed: constant speed, reverse, freeze frame, optional pitch keep. Done when: interpolation has unit tests for every mode and for edits between keyframes; each effect and transition has a frame hash at fixed parameters; stack order changes the result in a test; speed changes keep audio and video in sync in a test.
Phase 7: Titles and captions
Text clips: bundled open-licence fonts, size, weight, colour, stroke, shadow, background box, alignment, safe margins, animation through keyframes. Caption track: cue create, split, merge, shift, retime by dragging; styles; import and export SRT and VTT; burn in or export as a sidecar file. Speech-to-text is a provider interface only: with no provider configured, the control is not shown. Done when: SRT and VTT round-trip without loss on fixtures including malformed files; cue timing rules (no overlap, minimum duration, ripple with edits) have unit tests; burned-in caption frames match hashes.
Phase 8: Export
Formats: MP4 (H.264 + AAC) and WebM (VP9 + Opus), PNG frame, WAV audio. Presets: 1080p, 4K, vertical 1080x1920, square, custom. Range: whole sequence, in/out, or each selected clip or marker range as its own file (batch clipping). Per-clip reframe for vertical output. Export runs in a worker with progress, time remaining, cancel, and a queue. Streams to disk; memory stays bounded. Done when: frames handed to the encoder equal `renderFrame` output exactly; decoded frames of the exported file match preview at fixed times with PSNR of 40 dB or more; exported duration, frame count, and audio/video sync are verified by re-probing the file; cancel leaves no partial file; a 10-minute export completes within the memory budget; batch export of 20 ranges produces 20 valid files.
Phase 9: Project safety
Save, save as, open, recent projects, unsaved-changes prompt. Autosave every 60 s to a recovery file; crash recovery on next launch. Cache size limits with eviction. Error log the user can export. Done when: killing the app mid-edit and relaunching restores the work in a test; a project with offline media opens and can be relinked; cache never exceeds its limit in the soak test.
Phase 10: Desktop app and licensing

* Shell. Electron: context isolation on, node integration off, a narrow preload API, native open/save dialogs, `.cutline` file association, native menus, window state, single instance. A content security policy blocks all network access and a test asserts zero network requests in a full session.
* Installer. Windows installer and portable build; macOS and Linux targets configured. Original app icon. If this environment cannot download the Electron runtime, deliver the complete `desktop/` project with a one-click build script, run every test against the web build in headless Chrome, and state in the final report that the installer itself was not built or tested here.
* Ownership. `LICENSE` (proprietary, all rights reserved, © Chamod Gimhan), `EULA.txt`, and a generated `THIRD_PARTY_LICENSES.txt`. A test fails on any GPL, AGPL, or unknown licence in the dependency tree.
* Licence keys. Offline activation: a key is a signed payload (name, edition, issue date, optional expiry) verified with an Ed25519 public key embedded in the app. A separate `keygen` tool, not shipped in the app, creates keys; the private key is created on the owner's machine and is git-ignored. Without a valid key the app is fully usable and exports carry a small watermark. Activation, deactivation and status live in an About and Licence dialog. Done when: valid, tampered, expired, wrong-product and malformed keys each have a passing test; watermark presence and absence are checked by frame hash; the licence audit passes; the web build passes all smoke tests; the desktop build either launches and passes a smoke test, or the limitation is recorded as above.

Phase 11: Hardening and release
End-to-end workflows in headless Chrome: import, cut, add captions, colour, export, close, reopen, export again and compare. 30-minute playback soak. 50 open/edit/close cycles with heap, listener and DOM node counts compared. Fuzz: 100,000 random commands. Keyboard-only pass through every panel; contrast checked from theme values. Search the code for TODO, stub, placeholder and mock outside tests. README, shortcut reference, and `TEST_REPORT.md` generated from real results: counts, timings, every failure, every known limit. Done when: verify, smoke, render check, soak and fuzz are all green; "Known bugs" in PROGRESS.md is empty or each entry appears in TEST_REPORT.md with steps to reproduce; version tagged 1.0.0; final report delivered in 10 lines or fewer with the files.
